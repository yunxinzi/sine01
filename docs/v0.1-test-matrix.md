# V0.1 Test Matrix

The first milestone is not “AI completeness”. It is proving that the visual workflow is understandable, repeatable, and does not dead-end.

## Acceptance criteria

- Input accepts a meaningful brief and records uploaded-file metadata.
- Define asks no more than 6 high-impact questions and skips information already present in the brief.
- Explore always exposes 8 distinct Styleboards with cover/content/data context.
- Select can mix base style, layout, palette, and imagery language; the mixed result visibly affects preview output.
- Generate derives the deck title from the user brief and respects explicit/selected page count from 6 to 20 pages.
- Individual slide and whole-deck variants visibly change composition.
- Refresh preserves the current project through local storage.
- Deliver exports project JSON, a PNG deck ZIP, and a printable preview.
- No V1.0 feature is represented as completed when it is not implemented.
- CI must pass dependency audit, TypeScript checking, and production build.

## Five baseline scenarios

| Scenario | Input character | Expected stress point |
| --- | --- | --- |
| Classroom report | text-heavy, 8 pages | readable hierarchy and restrained density |
| Academic defense | research language, 12–14 pages | technical credibility and evidence rhythm |
| Competition pitch | visual-first, 9–12 pages | strong differentiation between Styleboards |
| Business report | data-first, 14 pages | structure and chart-like page rhythm |
| Image-led story | sparse text, 8 pages | whitespace, image language, and pacing |

## Manual regression path

For each scenario:

1. Start from Reset.
2. Paste a new brief that is unrelated to the built-in Weddell-seal sample.
3. Confirm adaptive questions do not repeat explicit information.
4. Select each of the 8 Styleboards at least once.
5. Mix layout from one board with palette from another.
6. Generate the deck and verify the topic and page count reflect the brief.
7. Regenerate one slide, then regenerate the whole deck.
8. Refresh the browser and confirm state is preserved.
9. Export JSON and inspect the stored design spec.
10. Export PNG ZIP and verify the file count equals the generated slide count.
11. Open print preview and confirm one slide is intended per printed page.

## V1.0 gate

Do not start Editable PPTX reconstruction until the five baseline scenarios can complete the V0.1 path without a broken control, misleading success state, or cross-slide visual collapse.
