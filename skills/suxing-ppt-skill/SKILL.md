# 苏醒 PPT｜高保真、可编辑、可审计的演示制作工作流

> 这是**工作流与验证 Skill**，不是声称自带图像生成模型、PPT 渲染引擎或 PowerPoint/WPS 的全自动程序。先检测当前环境能力，缺少时诚实告知，不能伪称实现。

## 0. 触发与工作模式

用户要求创建/修改 PPT、演讲文稿、幻灯片、答辩材料或图稿拼装时启用。读取当前上下文、用户素材、现有 `project.json` 和已确认节点；**不得反复询问已答过的问题**。

- `editable`（默认）：真正可编辑 PPTX，原生文字、形状、表格、图表优先，关键前景素材独立；按需动画。
- `image`：每页可以作为一张全尺寸图片放入 PPTX；明确标记“仅图片版，不可分层编辑”。**用户明确要求该模式时，不能强行重构。**
- `hybrid`：背景/复杂图为图片，文字和可动画主体原生或独立；逐页列出编辑边界。
- `review`：只检查/优化已有稿件；仅执行受影响阶段，无需强制重做8套风格。
- `pdf-only`：用户明确只要 PDF 时，可按目标格式交付；不要虚称 PPTX 已产生。

## 1. 不可省略的主要步骤与 Gate

| 阶段 | 行动 | 可核验产物 | 停止条件 / Gate |
|---|---|---|---|
| DEFINE | 读材料；仅集中询问真正缺失的关键约束；确定逐页事实与故事线 | `project.json` 初版、逐页文案 | 事实/约束足以设计 |
| EXPLORE | 制作**至少8套实际可见的16:9风格预览**，包含典型内容页；有构图和信息语言差异 | 8个 styleboard 图 | **用户选择或明确授权跳过** |
| PILOT | 选风格后先制作**最复杂代表页**并内部试装；检查字体、干净底图、独立主体及动画可行性 | 试装页和风险记录 | 关键方案可落地，无额外人工 Gate |
| ARTWORK | 生成完整各页高质量图稿，准确呈现最终文案与构图 | 全套定稿图（逐页ID） | **用户确认**，冻结 reference/design spec |
| REBUILD | 根据交付模式，真实分层与拼装到 PPTX；图稿驱动重建 | 元素映射、PPTX、可编辑性证据 | 不许截图冒充分层 |
| VERIFY | 逐页检查静态图、原生对象、动画及目标软件实播；改哪页复查哪页 | `qa-report.json`、最终导出预览 | 关键缺陷修复或明确披露 |
| DELIVER | **同一构建版本**输出 PPTX/PDF/预览/工程包；校验数量与文件可访问性 | 交付清单与真实链接 | 只宣称实际验证过的能力 |

**不可逆约束：** 只在 DEFINE 关键缺失、EXPLORE 选版、ARTWORK 全稿审核三个时点向用户集中要决策；用户明确放行后不要重复确认。用户已提供明确主题、风格或已确认页时，从现有节点继续，不能重启整条流程。默认 16:9、8–13 页，但用户要求优先，科研、竖版和长课件可例外。

## 2. 内容和审美原则

1. 先制定逐页论点/证据/信息密度，后生图；事实、公式、数据、引用不得擅改或编造。资料缺失时标注待核实。
2. 8套预览必须在构图、字体系统、空间语言、图像风格、信息表达至少多个维度显著不同，**不能仅换色**。风格由内容决定；「水墨入海」「黑银工业展」只作候选，不强加给所有项目。
3. 每页只承载明确表达任务；文字可读优先。禁止依赖极小字号、缺失标注、机械填满画布、无意义装饰、同一套模板复制所有页。
4. 图稿一旦确认，**锁定文案、画幅、主体关系和参考图片**；禁止以“提高编辑性”为借口无依据重设计。重大风格/构图改变才回到用户确认。

详细方案：[设计与图稿](references/visual-design.md)。

## 3. 分层构建：以“移动主体测试”作为硬门槛

1. 建立每页元素清单（`id/kind/source/bbox/layer/editable/animation`）与最终视觉稿一一对应；使用 `assets/project-template.json`。
2. `background`：完整、不带可移动主体残影的底图；可用已确认图稿的局部去字/补景，但要保持风格、机位、光影。
3. `text`：普通正文、标题、标签、数字与页码要用**原生文本框**；表格、简单结构图、图表尽量原生对象；复杂照片/绘画为独立图片。
4. `foreground`：被移动、替换、显隐或播放动画的对象必须为真实**透明独立素材**，不能仅裁剪整页原图矩形；移开后背景不得出现复制、残影、断层或接缝。
5. 元素拆分按语义动作单元，不盲目逐像素拆碎；记录坐标、裁切、比例、字体、换行、透明度、叠放层级与运动终态。
6. 非普通文字（字标/艺术书法）必须明确告知不能直接改字；图片整页允许用于 `image` 模式，但不得计入 `editable` 模式成功率。

详见 [真实分层验收](references/layering-and-editability.md)。

## 4. 动画先规划，再试验，再扩展

要动画时在设计阶段为其预留背景、出入场空间与遮挡；先让最复杂样页在**目标软件**测试。动画应体现叙事节奏、层级揭示、重点运动或场景转换；**全篇简单淡入不是高级动画**。分别记录进入/移动/强调/退出、触发、顺序、时长、终态。技术能力不足时交付“动画设计表”，标明“未实装”而非声称动画已生效。

详见 [动画兼容性](references/animation.md)。

## 5. 质量验收与失败恢复

- **静态 QA：** 当前渲染 vs 锁定图稿逐页并排，检查构图、色调、字距、边界、可读性、图片裁切与错字。数值相似度只是辅助，不能替代人工视觉检查。
- **编辑 QA：** 检查真正的原生对象；抽查修改文字、移动前景，确认底图完整。可运行 `python scripts/audit_pptx.py path/to/deck.pptx --mode editable` 做结构风险筛查，**不能把它当做真实打开编辑测试**。
- **动画 QA：** 检查触发、顺序、过程和终态；不同于 PPTX XML 是否含动画节点。
- **实播 QA：** 有目标软件条件时在 PowerPoint/WPS 实际测试首页、中间帧、末尾及导出；没有则明确“未实播”。
- 修复仅针对受影响页；同一错误连续两次修复无改善时暂停重试并定位根因/改方法；用户指定多轮迭代时照做，其他情况下不能无限空转。
- 按独立页面/素材适度并行，关键依赖与写回顺序串行；约15分钟或关键节点保存状态、资产索引、可恢复工程包；回读保存结果；不能把临时链接视为永久保存。

详细见 [验收标准](references/qa-and-gates.md) 和 [高效续作](references/speed-and-recovery.md)。

## 6. 最终交付协议

交付前核对实际文件存在、页数、版本和来源：PPTX / PDF / preview / assets 必须来自同一个 `build_id`。对外报告 `可编辑范围`、`图片化范围`、`动画规划/实装/实播状态` 和 `已检查/未检查项`；不能把“结构检查”“回读渲染”“WPS实际打开”混为一谈。交付纯图片版须明显标注。

详见 [交付与状态模板](references/artifacts-and-state.md)；脚本的真实功能和局限请读 [工具说明](references/tools.md)。
