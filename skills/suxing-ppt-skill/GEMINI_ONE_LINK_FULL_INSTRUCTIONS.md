# 苏醒 PPT｜高保真、可编辑、可审计的演示制作工作流

> 这是**工作流与验证 Skill**，不是声称自带图像生成模型、PPT 渲染引擎或 PowerPoint/WPS 的全自动程序。先检测当前环境能力，缺少时诚实告知，不能伪称实现。

## 0. 触发与工作模式

用户要求创建/修改 PPT、演讲文稿、幻灯片、答辩材料或图稿拼装时启用。读取当前上下文、用户素材、现有 `project.json` 和已确认节点；**不得反复询问已答过的问题**。

- `editable`（默认）：真正可编辑 PPTX，原生文字、形状、表格、图表优先，关键前景素材独立；按需动画。
- `image`：每页可以作为一张全尺寸图片放入 PPTX；明确标记“仅图片版，不可分层编辑”。**用户明确要求该模式时，不能强行重构。**
- `hybrid`：背景/复杂图为图片，文字和可动画主体原生或独立；逐页列出编辑边界。
- `review`：只检查/优化已有稿件；仅执行受影响阶段，无需强制重做8套风格。
- `pdf-only`：用户明确只要 PDF 时，可按目标格式交付；不要虚称 PPTX 已产生。

## 1. 不可省略的主要步骤与 Gate

| 阶段 | 行动 | 可核验产物 | 停止条件 / Gate |
|---|---|---|---|
| DEFINE | 读材料；仅集中询问真正缺失的关键约束；确定逐页事实与故事线 | `project.json` 初版、逐页文案 | 事实/约束足以设计 |
| EXPLORE | 制作**至少8套实际可见的16:9风格预览**，包含典型内容页；有构图和信息语言差异 | 8个 styleboard 图 | **用户选择或明确授权跳过** |
| PILOT | 选风格后先制作**最复杂代表页**并内部试装；检查字体、干净底图、独立主体及动画可行性 | 试装页和风险记录 | 关键方案可落地，无额外人工 Gate |
| ARTWORK | 生成完整各页高质量图稿，准确呈现最终文案与构图 | 全套定稿图（逐页ID） | **用户确认**，冻结 reference/design spec |
| REBUILD | 根据交付模式，真实分层与拼装到 PPTX；图稿驱动重建 | 元素映射、PPTX、可编辑性证据 | 不许截图冒充分层 |
| VERIFY | 逐页检查静态图、原生对象、动画及目标软件实播；改哪页复查哪页 | `qa-report.json`、最终导出预览 | 关键缺陷修复或明确披露 |
| DELIVER | **同一构建版本**输出 PPTX/PDF/预览/工程包；校验数量与文件可访问性 | 交付清单与真实链接 | 只宣称实际验证过的能力 |

**不可逆约束：** 只在 DEFINE 关键缺失、EXPLORE 选版、ARTWORK 全稿审核三个时点向用户集中要决策；用户明确放行后不要重复确认。用户已提供明确主题、风格或已确认页时，从现有节点继续，不能重启整条流程。默认 16:9、8–13 页，但用户要求优先，科研、竖版和长课件可例外。

## 2. 内容和审美原则

1. 先制定逐页论点/证据/信息密度，后生图；事实、公式、数据、引用不得擅改或编造。资料缺失时标注待核实。
2. 8套预览必须在构图、字体系统、空间语言、图像风格、信息表达至少多个维度显著不同，**不能仅换色**。风格由内容决定；「水墨入海」「黑银工业展」只作候选，不强加给所有项目。
3. 每页只承载明确表达任务；文字可读优先。禁止依赖极小字号、缺失标注、机械填满画布、无意义装饰、同一套模板复制所有页。
4. 图稿一旦确认，**锁定文案、画幅、主体关系和参考图片**；禁止以“提高编辑性”为借口无依据重设计。重大风格/构图改变才回到用户确认。

详细方案：[设计与图稿](references/visual-design.md)。

## 3. 分层构建：以“移动主体测试”作为硬门槛

1. 建立每页元素清单（`id/kind/source/bbox/layer/editable/animation`）与最终视觉稿一一对应；使用 `assets/project-template.json`。
2. `background`：完整、不带可移动主体残影的底图；可用已确认图稿的局部去字/补景，但要保持风格、机位、光影。
3. `text`：普通正文、标题、标签、数字与页码要用**原生文本框**；表格、简单结构图、图表尽量原生对象；复杂照片/绘画为独立图片。
4. `foreground`：被移动、替换、显隐或播放动画的对象必须为真实**透明独立素材**，不能仅裁剪整页原图矩形；移开后背景不得出现复制、残影、断层或接缝。
5. 元素拆分按语义动作单元，不盲目逐像素拆碎；记录坐标、裁切、比例、字体、换行、透明度、叠放层级与运动终态。
6. 非普通文字（字标/艺术书法）必须明确告知不能直接改字；图片整页允许用于 `image` 模式，但不得计入 `editable` 模式成功率。

详见 [真实分层验收](references/layering-and-editability.md)。

## 4. 动画先规划，再试验，再扩展

要动画时在设计阶段为其预留背景、出入场空间与遮挡；先让最复杂样页在**目标软件**测试。动画应体现叙事节奏、层级揭示、重点运动或场景转换；**全篇简单淡入不是高级动画**。分别记录进入/移动/强调/退出、触发、顺序、时长、终态。技术能力不足时交付“动画设计表”，标明“未实装”而非声称动画已生效。

详见 [动画兼容性](references/animation.md)。

## 5. 质量验收与失败恢复

- **静态 QA：** 当前渲染 vs 锁定图稿逐页并排，检查构图、色调、字距、边界、可读性、图片裁切与错字。数值相似度只是辅助，不能替代人工视觉检查。
- **编辑 QA：** 检查真正的原生对象；抽查修改文字、移动前景，确认底图完整。可运行 `python scripts/audit_pptx.py path/to/deck.pptx --mode editable` 做结构风险筛查，**不能把它当做真实打开编辑测试**。
- **动画 QA：** 检查触发、顺序、过程和终态；不同于 PPTX XML 是否含动画节点。
- **实播 QA：** 有目标软件条件时在 PowerPoint/WPS 实际测试首页、中间帧、末尾及导出；没有则明确“未实播”。
- 修复仅针对受影响页；同一错误连续两次修复无改善时暂停重试并定位根因/改方法；用户指定多轮迭代时照做，其他情况下不能无限空转。
- 按独立页面/素材适度并行，关键依赖与写回顺序串行；约15分钟或关键节点保存状态、资产索引、可恢复工程包；回读保存结果；不能把临时链接视为永久保存。

详细见 [验收标准](references/qa-and-gates.md) 和 [高效续作](references/speed-and-recovery.md)。

## 6. 最终交付协议

交付前核对实际文件存在、页数、版本和来源：PPTX / PDF / preview / assets 必须来自同一个 `build_id`。对外报告 `可编辑范围`、`图片化范围`、`动画规划/实装/实播状态` 和 `已检查/未检查项`；不能把“结构检查”“回读渲染”“WPS实际打开”混为一谈。交付纯图片版须明显标注。

详见 [交付与状态模板](references/artifacts-and-state.md)；脚本的真实功能和局限请读 [工具说明](references/tools.md)。

# 需求访谈、内容与八套视觉探索

## 输入约束
读取任务与已有素材，建立一个唯一 `project.json`。需要时一次性问：主题/受众/使用场景、演讲时间和页数、语言、16:9或其他比例、文字密度、图表与图片偏好、可否联网、源数据权限、交付格式、动画预期及软件版本。已有答案绝不重问。用户要求最简/竖版/纯图片的例外优先。

## 从内容提纲到图稿
每页设置：`intent`（单一表达目的）、`headline`（明确信息）、`evidence`（图片/图表/数据/引用）、`copy`（最终文字）、`layout_notes`（布局风险）、`assets`（来源和许可）。核对受版权保护素材的许可和引用；不直接搬用他人模板作为自有设计。中文或中英混排按真实行长预估换行。

## 八套风格卡
每套展示至少一个真实可见画面，推荐封面+典型信息页的紧凑缩略板；仅文字描述不得代替图像。可参考的差异维度：

| 编号 | 视觉方向示例 | 主要差异（不是只改色） |
|---|---|---|
| 01 | 水墨入海 | 留白、传统墨韵和现代资料块融合 |
| 02 | 黑银工业展 | 机械宏观摄影、金属边缘光、深色网格 |
| 03 | 大字编辑设计 | 排版主导，摄影切割，强文字层级 |
| 04 | 学术杂志 | 数据复合图、脚注系统、理性网格 |
| 05 | 自然叙事 | 大幅纪实摄影与细腻空间留白 |
| 06 | 轻量信息可视化 | 流程、卡片、图表与微符号 |
| 07 | 科技展馆 | 空间深度、线框界面和结构剖视 |
| 08 | 极简国际演讲 | 极少元素、强调结论与数值对比 |

以上是*可替换方向*；须按主题另行生成，避免固定套八种。每种具体给出主色、字体、构图、图片语言、信息密度及动画空间。用户可混搭，锁定 Design Spec 后所有批次复用同一规范。

## 复杂样页试装
风格选定后，从内容最多、主体最多、动效最难的页面中挑一张，试验：字体可落地、文字换行合理、背景去字干净、前景能独立移动、PPTX可打开、目标软件动画方法可实现。内部失败可重做样页，不需要用户多一个审批节点。

## 图稿审核 Gate
展示所有正式页的完整设计稿，顺序、准确文案、构图、图层视觉、引用可读。用户确认后保存原图/哈希/页序/版本为不可变基准；之后用同基准对照渲染，不擅自改变主题设计。

# 分层与编辑性验证协议

## 对象类别
- `background`: 静态背景/场景；保留原图空间关系且去掉可移动对象。
- `native_text`: 可在 WPS/PowerPoint 中直接编辑的文字。记录字体回退与换行约束。
- `native_shape`: 形状/曲线/基础流程结构，提供可编辑参数。
- `native_chart` / `native_table`: 原生图表和表格，数值另有来源。
- `independent_image`: 透明独立图像，能移动/隐去而不显露原图副本。
- `flattened_page`: 仅允许在用户明确要求的图片版，或在受阻时明确披露的降级页。

## 拼图测试 (不可用截图裁片欺骗)
1. 导出已确认完整画面的参考图 `reference.png`。
2. 生成或分离背景 `background.png`；若为去字/移除前景，需补全遮挡的真实底景，严禁主体残影。
3. 按视觉顺序插入独立主体；绘制原生文字。严格对齐 bbox、行距、间距、透明度和层级。
4. **移动主体测试**：在演示文稿中移动一个主要前景对象至少到旁边可见区，原位置底图必须自然连续；恢复位置再验证。
5. **编辑文字测试**：修改1处标题及1处普通正文，PPT 内真实文本对象随之变化；还原后确认换行与字体正确。
6. **对象结构测试**：页内实际存在原生对象；XML中存在图片不能直接证明独立素材可靠，必要时人工检查。

## 禁止行为
- 把整页截图塞到背景，上面再放一张从相同图截出的前景、造成视觉重影。
- 用单张整页图包装成“可编辑 PPT”。
- 用大量普通淡入数量替代合理动画设计。
- 因源工具不支持结构化输出，就谎称已经分层或已实播。

## 视觉还原方法
逐页对比: 大轮廓→区域布局→内容准确度→字体与字距→图像材质→层级边界。只对差异区域进行修正。大量相同纹理和细节若复杂不可拆，可整体作为不可动画背景保留；保持视觉而不是盲目把所有像素对象化。若可编辑要求与画面保真存在实质冲突，提供范围清晰的权衡说明和图片/混合版，不偷偷降级。

# 动画预规划与兼容性

## 编排前置
在图稿阶段划分背景、主要动作单元、独立文字层、遮挡层、终态位置；记录每步 `trigger/target/effect/start/duration/end_state/dependency`。静态设计必须为移入/移出/遮罩预留画面。

## 动画设计层级
- 信息型：按阅读顺序分组揭示，避免一行一动造成冗余。
- 结构型：局部展开、对比滑移、分层剖示、过程箭头，使用软件可支持的真实对象。
- 场景型：多层景深/对象转换/章节转场；必须验证在目标客户端的细节。
- 无动画型：讲课/打印/纯PDF场景可跳过动画；不强制增添。

## 检查四阶段
1. Design：预规划并冻结对象身份、入场/终态。
2. Build：实际生成动画序列或仅留动作设计表，状态不得混用。
3. Inspect：检查PPTX时间轴、对象引用、开始/结束状态。
4. Play：PowerPoint/WPS目标版本实播，观察帧间遮挡、字体、布局与性能。

### 不夸大能力
XML中存在 `p:timing` 只表明文件里有时间节点，不保证软件播放兼容；无法实播时记录 `not_tested`。需要流体墨迹、逐笔书写等难以由PPT对象原生实现的复杂效果，须声明视频或特殊插件替代需求，不得默认声称可编辑/可在WPS播放。

# 验收标准（Gate Policy）

| 门槛 | 最低证据 | 不合格处理 |
|---|---|---|
| 需求 | `project.json` + 逐页主题/关键事实 | 补齐影响正确性的要点 |
| 视觉探索 | 8套可见图与选版记录（除用户明确豁免） | 补足构图多样性 |
| 试装 | 复杂样页的渲染+主体移走检验（需可编辑时） | 先修技术路线再批量 |
| 图稿锁定 | 全套参考图+确认标记+文案版本 | 未确认不得批量正式构建 |
| 静态 | 所有最终页面渲染，参考图对照，无严重错漏 | 页级局部修复 |
| 编辑 | 原生文字/形状与独立前景抽查 | 修正分层或披露图片限制 |
| 动画（按需） | 对象/触发/过程/终态一致 | 调整动作或标注未实现 |
| 实播（条件允许） | 目标软件实际打开并留测试记录 | 未测需明确说明 |
| 交付 | 同一 `build_id` 的所有文件、实存校验 | 重新生成不一致文件 |

## 静态检查
逐页比对用户锁定图稿及对应渲染: 信息完整、事实可核查、文字与行宽可读、图片不畸变、对齐/裁切合理、无遮挡、无黑屏/空白/半页黑色、全套有节奏变化。检查页序和图稿ID关联。允许使用MAE/SSIM/热图发现差异，但不可用单独阈值宣称审美合格。对比需同尺寸、同颜色空间，不随意拉伸。图稿与交付版本相同。

## 故障优先级
- `BLOCKER`: 文件损坏、空白页、整图伪分层、内容虚假、目标软件无法播放关键内容；阻止交付。
- `MAJOR`: 文字溢出、主体残影、流程错误、重要图表数据不一致、动画错误；修复或明确披露后才可交付。
- `MINOR`: 微小字距、边框装饰等；评估代价后局部调整。

## 检测能力诚实分层
`structural` = ZIP/XML结构检查；`rendered` = 本环境渲染；`editable_test` = 真实修改对象；`target_playback` = 目标PowerPoint/WPS中实播。不可推断高层测试由低层测试自动完成。

## 循环策略
构建过程中及时验收；最后检查每一页。用户指定固定3轮则每轮记录具体缺陷和变化；未指定的项目禁止无根据重复3次。同类问题两次无改善先定位根因或换工具。无阻断缺陷时立即停止重做。

# 提速与可靠续做（V1.9 的核心）

目标是在**不跳过审查、不偷换素材、不降低保真度**的前提下降低等待与返工。

1. 用单一 `project.json` 统管需求、页表、实际素材、坐标、动画、Gate 状态和导出文件，不复制维护多个内容不一致的清单。
2. 锁定共享字体/调色板/模板后，允许检索、独立风格稿、无依赖素材和独立页并行；用户审批、依赖性构建和对共享文件写入必须串行。
3. 局部修复：以页ID/元素ID定位。错字仅改文字框，局部背景修补不重造整个画面；工具被迫全量导出也须保证未改页面仍与原基准对应。
4. 缓存原图与确认图稿，不重下载/上传；素材带 SHA-256、源文件、使用页、版本。
5. 每完成页/批做快速检查；约15分钟或关键 Gate 结束后保存工程与 `project.json`，包含当前stage、待办、未验证项、真实存储位置。对保存成功要回读，不能把临时下载链接当作云端持久保存。
6. 恢复时先验证状态文件的实际产物存在，再继续最新已验收 Gate；聊天记录仅作为线索而非唯一事实。
7. 重试同一错误2次无改善必须改变方法；并发不稳定时收缩并发度。
8. 仅记录真实的生图/构建/渲染/保存耗时和故障；不得编造“快了70%”之类数字。

# 文件与状态约定

## 推荐项目目录（示例）

```
workspace/<project_id>/
  project.json                  # 唯一事实源（可使用 assets/project-template.json）
  styleboards/01.png ... 08.png
  reference/slide-01.png ...
  assets/backgrounds/*.png
  assets/foregrounds/*.png
  builds/<build_id>/deck.pptx
  builds/<build_id>/deck.pdf
  builds/<build_id>/preview/slide-01.png ...
  builds/<build_id>/qa-report.json
```

素材引用用相对路径；同一构建版本绑定同一 `build_id`。保存每个产物的 SHA-256，禁止拿旧 PDF/图片冒充最新 PPTX 的导出。可选 `manifest` 字段记录 `build_id`, `source_build_id`, `renderer`, `export_timestamp`, `actual_verification`。

## 各模式交付
- `editable`: 真实可编辑 `.pptx`、全页预览；按需 `.pdf`、可重建素材和动画描述。
- `image`: 纯图片 `.pptx` 与逐页图片（按需 PDF），必须明确“不能分层编辑”，禁止夸大。
- `hybrid`: `.pptx` 与按页的编辑性边界表，明确 `flattened` 素材。
- `pdf-only`: PDF 与按需预览，不声称 PPTX 已有。
- `review`: QA报告、已修改文件和差异说明；修改后仍执行受影响页面验证。

## 跨环境运行
工程所需生成/渲染/校验工具因Agent而异。优先使用实际可运行的工具组合；不把某一种Python/PPT生成库写死为工作流必要条件。若某项条件无法满足，精确说明影响范围并给出能诚实交付的产物。

# 附带脚本与边界

脚本均使用 Python 3.10+，除图像对比脚本外只依赖标准库。

- `scripts/validate_skill.py`: 检查 Agent Skills 元信息、内部相对链接和基础目录结构；不代表平台官方认证。
- `scripts/validate_project.py`: 检查 project.json schema、阶段门槛声明和素材映射，属于**声明一致性检查**，不等于用户真的确认过。
- `scripts/audit_pptx.py`: 解析 PPTX ZIP/XML，统计页面对象、文本框、图片和动画结构；可标记整页一图与空白。无法证明图片真透明、字体匹配、背景无残影、在 WPS 可编辑或动画可播放。
- `scripts/compare_renders.py`: 比较两张等尺寸渲染图，输出绝对误差热力图与MAE。需要 `Pillow`（可 `pip install Pillow`）；视觉数值只辅助人审。

示例：

```bash
python scripts/validate_skill.py .
python scripts/validate_project.py assets/project-template.json
python scripts/audit_pptx.py path/to/deck.pptx --mode editable --json build/audit.json
python scripts/compare_renders.py reference/slide-01.png builds/run-01/preview/slide-01.png --heatmap build/heatmap-01.png
```

未包含任何生成模型 API key，未绑定特定商业供应商，外部工具的版权、权限、价格和限额由使用者自行管理。
